# my-tor-gateway

Домашний "VPN" на базе Tor для Termux — раздаёт SOCKS5-доступ через Tor
(с поддержкой мостов) на другие устройства в локальной сети, с
авторизацией по логину/паролю.

## Что где

| Файл | Зачем |
|---|---|
| `setup.sh` | Запустить один раз — ставит всё необходимое |
| `start_tor_vpn.sh` | Запускать каждый раз — поднимает всё одной командой |
| `new_identity.sh` | Сбросить цепочки Tor (новый видимый IP) без перезапуска сервиса |
| `bridges.txt` | Ваши мосты — просто вставляйте строки, без правки torrc |
| `config.env` | Логин/пароль/порт, режим логов и настройки автообновления/автоперезапуска |
| `tor_socks_gateway.py` | Сам SOCKS5-шлюз с авторизацией (используется скриптом автоматически) |

`torrc` больше не редактируется руками вообще — `start_tor_vpn.sh`
собирает его сам при каждом запуске из `bridges.txt` и текущего IP
телефона.

## Установка (один раз)

```bash
pkg install git -y
git clone https://github.com/ВАШ_ЛОГИН/my-tor-gateway.git
cd my-tor-gateway
chmod +x setup.sh
./setup.sh
```

Затем:
1. Откройте `bridges.txt` и вставьте свои мосты (по одной строке на мост)
2. Откройте `config.env` и задайте свой логин/пароль

## Запуск (каждый раз)

```bash
./start_tor_vpn.sh
```

Скрипт сам:
- подтянет обновления кода из GitHub (если `AUTO_UPDATE=1` в config.env)
- поставит недостающие пакеты, если их нет
- соберёт `torrc` из `bridges.txt` и текущего IP телефона
- запустит Tor, дождётся полного подключения
- перезапустит Tor автоматически, если он упадёт (если `AUTO_RESTART=1`)
- запустит SOCKS5-шлюз с авторизацией
- выведет данные для подключения других устройств

Остановка — `Ctrl+C`.

## Ещё проще: автозапуск

Чтобы вообще не открывать вручную и не запускать команду:

```bash
echo 'cd ~/my-tor-gateway && ./start_tor_vpn.sh' >> ~/.bashrc
```

Теперь достаточно просто открыть Termux.

## Приватность и анонимность

Что уже встроено:

- **Tor больше не торчит в LAN напрямую.** Раньше `SocksPort` был
  привязан к IP телефона — теоретически можно было обойти авторизацию
  шлюза и подключиться прямо к Tor. Теперь `SocksPort` только на
  `127.0.0.1`, единственная дверь наружу — авторизованный шлюз.
- **Нулевое логирование по умолчанию** (`LOG_MODE=off` в `config.env`).
  В логах не остаётся ни IP подключившихся устройств, ни того, какие
  сайты они открывали — только факт ошибок без деталей. Можно
  переключить на `minimal` (события без адресов) или `verbose`
  (полные логи для отладки).
- **Изоляция цепочек Tor между устройствами.** Каждое новое
  подключение к шлюзу получает случайный одноразовый токен, который
  передаётся в Tor как SOCKS5-логин — это гарантирует, что два разных
  устройства в вашей сети не окажутся на одной и той же цепочке Tor
  (Tor использует разные логины для `IsolateSOCKSAuth`).
- **`SafeLogging` и `AvoidDiskWrites`** в torrc — Tor маскирует
  чувствительные адреса в собственных логах и минимизирует запись на
  диск.
- **`./new_identity.sh`** — команда "сбросить личность": просит Tor
  построить новые цепочки (новый видимый IP для сайтов) без
  перезапуска всего сервиса. Уже открытые соединения на скорость не
  влияет — они просто доживают на старых цепочках, новые пойдут по
  свежим.
- **`PARANOID_WIPE_STATE=1`** в `config.env` — полная зачистка
  состояния Tor (кэш узлов, guard-ноды) перед каждым запуском. Не
  трогает скорость работающих соединений, только увеличивает время
  начального bootstrap.

### Важные честные оговорки

- **Это защищает "кто подключался" и "куда шёл трафик" на уровне
  IP/сети — но не браузерный отпечаток.** Если через прокси ходит
  обычный Firefox/Chrome, сайты всё равно могут узнавать вас через
  cookies, canvas-fingerprinting, вход в аккаунты и т.п. — Tor меняет
  только видимый IP, а не поведение самого браузера. Для реальной
  анонимности "что смотрели" на уровне сайта нужен именно **Tor
  Browser** на клиентском устройстве, а не обычный браузер через
  SOCKS5.
- **Локальный отрезок (телефон ↔ устройство в Wi-Fi) не зашифрован**
  сам по себе — это ограничение протокола SOCKS5. Если в вашей сети
  есть недоверенные устройства, это отдельный риск (что именно
  запрашивается, до шифрования Tor). Практическая защита — WPA2/WPA3
  с паролем, которому вы доверяете, плюс сам SOCKS5-логин/пароль как
  фильтр от чужих устройств.
- **Логи Tor Browser/сайтов на стороне назначения** (аналитика,
  отпечаток устройства) этим скриптом не контролируются — это уже
  вне зоны ответственности сетевого шлюза.

## Скорость

Что уже встроено, без ущерба анонимности между вашими устройствами:

- **Изоляция цепочек — на устройство, а не на каждое соединение.**
  Раньше каждое новое TCP-подключение получало свой токен для Tor,
  а браузер при загрузке одной страницы открывает десятки
  параллельных соединений — почти каждое улетало на новую цепочку,
  то есть на каждое лишнее время построения цепочки. Теперь токен
  один на устройство в течение 10 минут (как раз совпадает с тем,
  как часто Tor и так меняет цепочки по умолчанию) — параллельные
  запросы браузера идут по уже готовым цепочкам. Разные устройства
  в сети по-прежнему не делят цепочки друг с другом.
- **TCP_NODELAY** на обеих сторонах туннеля — убирает задержку
  Нэгла, заметно для отзывчивости при открытии страниц.
- **Буфер перекачки увеличен с 8 КБ до 64 КБ** — меньше системных
  вызовов на объёмных закачках.

Дополнительно, ценой части защиты от анализа трафика (обычно
не критично для домашнего использования):

- **`DISABLE_CONN_PADDING=1`** в `config.env` — отключает служебный
  padding-трафик Tor, немного экономит накладные расходы.

Что не входит и почему: количество узлов в цепочке (обычно 3) —
это фундаментальная часть модели анонимности Tor, уменьшать его
нельзя без потери сути технологии. Если нужна именно высокая
скорость в первую очередь — см. предыдущий раздел про то, чем это
принципиально не является обычным VPN.

## Обновление мостов

Мосты иногда "протухают". Просто отредактируйте `bridges.txt`,
сохраните и перезапустите скрипт — правки в `torrc` вручную не нужны,
всё соберётся заново само.

## Работа по многу дней без перезапуска

Скрипт рассчитан на длительную непрерывную работу:

- **И Tor, и сам шлюз перезапускаются автоматически**, если упадут
  (watchdog для обоих, не только для Tor).
- **Лог Tor обрезается**, если разрастётся больше ~5 МБ — как при
  старте, так и раз в 4 часа во время работы, чтобы не забить память
  телефона за несколько дней.
- **Зависшие клиентские подключения** (когда устройство подключилось,
  но ничего не передаёт) отваливаются по таймауту 30 секунд на этапе
  авторизации, не занимая поток вечно.

Что стоит сделать дополнительно для максимальной стабильности:

1. **Отключить ограничения батареи** для Termux в настройках Android
   (Настройки → Приложения → Termux → Батарея → "Без ограничений").
   Без этого Android может убить процесс в фоне даже с wake-lock.
2. **Держать экран телефона не обязательно включённым** — `termux-wake-lock`
   не даёт "уснуть" процессору, но экран может быть выключен.
3. **На случай перезагрузки телефона** (обновление системы, разрядка
   батареи и т.п.) сам процесс не поднимется автоматически — Termux не
   запускается при загрузке системы без дополнительных настроек.
   Чтобы это исправить, поставьте отдельное приложение **Termux:Boot**
   (из F-Droid, от тех же разработчиков) и создайте файл
   `~/.termux/boot/start-gateway.sh`:
   ```bash
   #!/data/data/com.termux/files/usr/bin/bash
   termux-wake-lock
   cd ~/my-tor-gateway
   ./start_tor_vpn.sh
   ```
   и сделайте его исполняемым: `chmod +x ~/.termux/boot/start-gateway.sh`.
   Тогда шлюз поднимется сам даже после перезагрузки телефона.
